# Changelog

## Unreleased (0.5.0)

- Change (K5, workflow gate order and middleware): `Authorize` / `AuthorizeAsync` now refuse a required-and-absent workflow step (403, check `workflow`) BEFORE decoding the PCActn, and an undecodable PCActn is 401 with check `pcactn` and reason `undecodable PCActn: ...` (was check `wire`, `wire: PCActn could not be decoded`; an absent PCActn stays `wire: no PCActn presented`), so the gate never judges an unreadable proof. `PcaMiddleware` reads the workflow step from `PcaAuthorizeOptions.WorkflowCall`, else from the JSON body member `workflow` {commitment, receipts, step, units, goal_digest} when the PCActn came in the body (a present but malformed member is an empty call, which the gate denies). Tests: `MiddlewareWorkflowTests`; the shared fixture replay now includes the three undecodable-PCActn cases.
- **Breaking (K5, security default flip):** `plan_root_authorized` is enforced by default. When the pipeline is given no plan nodes and no plan authorization (`AuthorizeInput.Plan` null/unset and no registered plan), the check now FAILS with `plan_root_authorized: default-deny: no authorized plan is configured for this verifier (supply the plan and its authorization, or set InsecureSkipPlanRootCheck)` instead of reporting `not-enforced`. `Authorize` / `PcaOptions` do not accept an `InsecureSkipPlanRootCheck` opt-out (they already required this check to pass); the `Conformance` runner is unaffected.

New `IntentPolicy(Require, MinFidelityPpm, MaxResidualRiskPpm)` record (`IsActive`, `IntentPolicy.FromJson(object?)`; a set but negative / fractional threshold fails closed), `Pca.IntentGoal`, `Pca.IntentGoalCommit`, `Pca.ValidateIntentWire`, `Pca.DecideIntent`, and an optional trailing `IntentPolicy? intentPolicy = null` parameter on `Pca.VerifyRaw` / `Pca.VerifyPcactnCore`. ASP.NET Core: `PcaOptions.IntentPolicy` (default null) is forwarded to the verifier. Existing calls (no policy, no `intent` field) return the same verdict as before. The Conformance runner, `CorpusTests`, `Snapshot` and the diff-fuzz driver pass `context.intent_policy` / `intent_policy` through.
- Intent policy thresholds are valid iff their NUMERIC value is a safe integer >= 0, whatever the JSON spelling (`950000.0` and `1e6` are accepted; `950000.5`, negatives, `-0.0`, NaN/Infinity, values above 2^53-1, null, bools and strings are a misconfiguration and fail closed). New `IntentPolicy.FromJsonText(string)` parses raw policy JSON with the lenient parser, so the number spelling reaches the check. Conformance runners and the diff-fuzz driver accept `intent_policy_json` (raw JSON text; it wins over `intent_policy` when both are present).

## 0.4.1

- Security (policy layer): caveats on the root grant outside the envelope are now evaluated like delegated caveats; new policy_caveats/evaluate_caveats helpers (incl. max_spend). The core verifier still does not evaluate caveats. .NET: `Caveats.PolicyCaveats(grant, chain)` (the grant's caveats minus its first `envelope` caveat, then the caveats the hops appended) and `Caveats.EvaluateCaveats(caveats, ctx)` -> `Caveats.Result(Ok, Failed)` (total; `expires`, `not_before`, `rate`, `max_blast_radius`, `reversibility_max`, `delegation_depth`, `budget_alloc`, and the new `max_spend {usd}`; anything else fails closed). `Pca.VerifyPcactnCore` and the ASP.NET Core `PcaMiddleware` are unchanged and still treat caveats as opaque: a resource server enforcing a grant's caveats calls `Caveats.EvaluateCaveats(Caveats.PolicyCaveats(grant, chain), ctx)` with its own action params (snake_case context keys, as in the `primitives.caveat_eval` vectors). New `primitives.caveat_eval` vectors run in the Conformance runner and `R041Tests`.
- Wire: threshold-share signatures are validated per suite (`Pca.ValidateShareSignatureWire`): `alg` absent = ed25519 (64-byte `sig`, no `pq_sig`), `ml-dsa-65` (3309-byte `sig`, no `pq_sig`), `hybrid-ed25519-ml-dsa-65` (64-byte `sig` + 3309-byte `pq_sig`); a non-string (incl. null) or unknown `alg` is a wire refusal. Before, every share `sig` had to be 64 bytes, so a pure ML-DSA-65 share could not be carried. A share's `pq_pk` is still judged only by the threshold check. Reason text is now `threshold.shares[i]: 'sig' is not canonical base64url (N bytes) for alg '<alg>'`. The Conformance runner and `CorpusTests` skip a vector whose `requires` names a registered suite this verifier does not implement.
- Middleware: the `PCA-Action` header is decoded STRICTLY (`Pca.DecodePcaHeader`, null when invalid): unpadded base64url only (no padding, standard alphabet or whitespace; nothing is trimmed) and well-formed UTF-8. Invalid UTF-8 (overlong forms, encoded surrogates, truncated sequences) used to be replaced with U+FFFD and reach the JSON parser; it is now the 401 `not canonical base64url` path. A leading BOM is kept (and refused by the strict JSON parser). New `primitives.pca_header` vectors run in the Conformance runner, `R041Tests` and `PcaMiddlewareTests`.
- Version: `<Version>0.4.1</Version>` in AtlasPca.csproj and AtlasPca.AspNetCore.csproj (no version was set before).
